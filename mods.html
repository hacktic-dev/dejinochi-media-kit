Modding guide · API v1

Build on Dejinochi

Dejinochi supports content packs and executable gameplay mods. This guide covers the package format, the sandboxed DejiScript language, the public Mod API, custom screens and minigames, persistent state, security, and publishing to Steam Workshop.

Game 1.1.x API v1 DejiScript sandbox Data + code mods

Overview

There are two kinds of Dejinochi mod. Both can be installed from a local folder, a ZIP, or a Steam Workshop subscription.

Data mods

JSON files and images that add or replace pets, shells, stickers and pixel assets. They are merged after the base content and do not execute code.

Code mods

A manifest plus a DejiScript entry point. Code mods can register screens, menu entries and minigames, react to game events, run simulations and persist their own state.

DejiScript is not GDScript. Dejinochi never loads a mod’s .gd file, native library, Godot scene or resource pack. Code mods run inside a host-side interpreter that only exposes the public api object and plain data values.

What code mods can do

  • Register custom screens and Games-menu entries.
  • Draw pixel UI with rectangles, text, images, buttons and hit regions.
  • Register complete custom minigames with their own update/input loops.
  • Subscribe to stable gameplay events such as feeding, sleeping and graduation.
  • Read a pet snapshot and apply validated pet effects.
  • Store namespaced persistent data with schema migrations.
  • Query loaded base and modded content.

What code mods cannot do

  • Access the scene tree, nodes, engine classes, OS, files, Steam or the network.
  • Call another mod’s API or read another mod’s storage.
  • Change official achievements, Steam stats or base-game progression totals.
  • Run indefinitely or allocate unbounded data; execution and storage budgets are enforced.

How mods load

Dejinochi scans every folder and .zip in the player’s mods directory. Steam Workshop items are read directly from Steam’s library folders and are not copied into the manual mods directory.

  1. Base game content loads first.
  2. Workshop items load next, ordered by numeric item id.
  3. Manual folders load alphabetically.
  4. Manual ZIPs load alphabetically.

Later data sources can override earlier content by reusing an id. Code mods are validated independently and are only executed when enabled and compatible with the running API version.

Restart after code changes. Installing, enabling, disabling, or updating a code mod may require restarting Dejinochi. Running code is never hot-swapped when its script or manifest changes; the old code stops and the update is applied on the next launch.

Install & enable

Copy the whole mod folder into the local mods directory:

  • Windows: %APPDATA%/Godot/app_userdata/Dejinochi/mods/
  • Linux: ~/.local/share/godot/app_userdata/Dejinochi/mods/

Start Dejinochi, open Settings → Mods → Installed mods, select the mod and confirm it is enabled. The detail screen labels code mods and lists their requested capabilities. A code mod cannot run if its manifest is invalid, it requests a newer API version, or a required dependency is missing or disabled.

Workshop subscribers can enable or disable an installed item without subscribing or unsubscribing. Steam remains responsible for downloads, updates and removal.

Your first code mod

This minimal mod subscribes to feeding and shows a caption. It uses only the events and notify capabilities.

hello_pet/manifest.json

{
  "id": "you.hello_pet",
  "title": "Hello Pet",
  "author": "Your name",
  "version": "1.0.0",
  "type": "script",
  "entry": "main.sgd",
  "api_version": 1,
  "min_game_version": "1.1.0",
  "capabilities": ["events", "notify"]
}

hello_pet/main.sgd

function on_init()
    api.subscribe("pet.fed", on_fed)
    api.notify("Hello Pet is installed!")
end

function on_fed(payload)
    api.notify("Yum! " + str(payload.food) + " for " + str(payload.pet.name) + ".")
end

Package layout: 

hello_pet/
  manifest.json
  main.sgd
  README.md
  preview.png        (optional, used by the Workshop uploader)

Copy the folder into the mods directory, restart Dejinochi, enable Hello Pet in the Mods screen, then feed the pet. The custom caption appears in the normal feedback area.

If the mod does not appear, check the Godot output for [Mod you.hello_pet] lines. A manifest, entry-point or capability error is reported there and in the Mods detail screen.

Package layout

A mod is a folder or ZIP with files at its root (or inside one wrapper folder in a ZIP). Paths in the manifest and scripts are always relative to the mod root. 

my_mod/
  manifest.json        required
  scripts/main.sgd     required for code mods
  assets/sprites.png   optional, loaded through api.load_image
  preview.png          optional Workshop preview image
  README.md
  pets.json            optional data-mod content
  shells.json
  stickers.json
  assets.json
  • Absolute paths and paths containing .. are rejected.
  • Symbolic links are rejected for executable packages and publishing.
  • Script entries are limited to 256 KiB; images to 2 MiB and 1024 pixels per side.
  • ZIP expansion is limited to 64 MiB and 2,000 entries.

Data mods

Data mods add or replace pets, shells, stickers and pixel assets. They use pets.json, shells.json, stickers.json and assets.json. Content ids should be namespaced, for example author.form.fern. 

{
  "title": "Fern Pack",
  "author": "Author",
  "version": "1.0.0",
  "icon": ["..##..", ".####."],
  "icon_scale": 2
}

Data mods are merged base-first. Reusing a form id replaces its complete definition; reusing an asset key replaces that value. Modded collectible species and stickers appear in collections but never increase the base-game achievement totals.

See the game repository’s content/README.md for the complete JSON schemas for forms, sprites, conditions, shells, stickers and assets.

DejiScript

DejiScript is a deliberately small language with GDScript-like syntax. The game parses and executes its AST directly. There is no JIT, no native code, no imports, no engine reflection and no access to the global GDScript scope. 

var visits = 0

function on_init()
    api.subscribe("pet.fed", on_fed)
end

function on_fed(payload)
    visits = visits + 1
    if visits >= 3:
        api.notify("That is three meals today!")
    else:
        api.notify("Meal " + str(visits))
    end
end

Execution model

  1. The entry script’s top-level statements run once.
  2. on_init() runs if present.
  3. on_activate() runs after initialization if present.
  4. Registered callbacks run from host events, screen/game ticks and timers.
  5. on_deactivate() runs when the mod is disabled or the game closes.

Top-level var declarations persist for the session and are shared by the mod’s functions. Functions capture their defining scope, so callbacks can mutate top-level state.

Syntax at a glance

# Comments start with a hash.
var name = "Kerochi"
var speed = 1.5
var items = ["seed", "water"]
var state = {"seeds": 5, "water": 3}

function greet(who)
    return "Hello, " + who + "!"
end

if state.seeds > 0:
    state.seeds = state.seeds - 1
elif state.water > 0:
    state.water = state.water - 1
else:
    api.log("Nothing to use.")
end

while state.seeds < 5:
    state.seeds = state.seeds + 1
end

for item in items:
    api.log(item)
end

Colons after if, elif, else, while, for and function headers are optional. Every block ends with end.

Operators

  • Arithmetic: + - * / %
  • Comparison: == != < <= > >=
  • Logic: and, or, not (short-circuiting)
  • Assignment: = += -= *= /= %=
  • Access: object.member, container[index], call(args)

+ concatenates strings and arrays, and adds numbers. Use str(value) when mixing values into text. Truthiness follows the usual rules: nil, false, 0, empty strings, empty arrays and empty dictionaries are false.

Collections

var plots = [
    {"planted": 0, "boost": 0},
    {"planted": 0, "boost": 0}
]

plots[0].planted = api.now()
var first = plots[0]
var count = len(plots)

for index, plot in plots:
    plot.boost = plot.boost + 10
end

Arrays and dictionaries are reference values. Assigning one to another variable shares the same container. Use api.storage_get for a fresh copy of persisted data.

Control flow & functions

Functions are declared with function, accept positional parameters, and return with return. Missing arguments become nil; extra arguments are rejected. 

function stage_of(plot)
    if plot.planted <= 0:
        return 0
    end
    var elapsed = api.now() - plot.planted + plot.boost
    if elapsed < 20:
        return 1
    elif elapsed < 55:
        return 2
    elif elapsed < 100:
        return 3
    end
    return 4
end
  • break leaves the nearest loop.
  • continue starts the next iteration.
  • pass is an explicit no-op.
  • Recursion is allowed up to the call-depth limit.
  • Functions cannot be overloaded; the latest declaration wins in its scope.

There are no classes, modules, imports, coroutines, await, exceptions, try/catch, or engine globals. Keep module-level data in top-level variables and organize code with functions and dictionaries.

A parse error, denied capability, invalid API argument or exceeded limit records an error and disables that mod. Other mods and the game keep running. Errors include the mod id and appear in the Godot output and the Mods detail screen.

The public API

Every script receives one global object, api, plus the built-in functions above. The API is versioned, capability-checked and intentionally small: registrations, events, host services, storage and content queries are separate groups covered in the following sections.

GroupTypical callsCapability
Registrationregister_screen, register_menu_entry, register_minigameui, minigames
Eventssubscribe, on, register_updateevents
Host servicespet, game_time, apply_effect, notify, open_screen, sfxpet.read, pet.modify, notify, ui
Persistencestorage_get, storage_set, on_migratestorage

Utilitynow, log, mod_id, api_version, has_capability—

Calling a method without its capability fails the current callback and disables the mod with a diagnostic. All arguments are validated before the host acts.

Lifecycle

The script runs in a private environment with one global object: api. It also has the built-in functions listed above.

CallbackWhen it runs
on_init()Once after the entry script is parsed and top-level code has run.
on_activate()After initialization and storage migrations succeed.
on_deactivate()When the mod is disabled, updated or the game closes.
 
var activated = false

function on_init()
    api.log("Initializing " + api.mod_id())
end

function on_activate()
    activated = true
end

function on_deactivate()
    api.log("Goodbye")
end

Screens & menu entries

A screen is a dictionary with a local id and callbacks. Register the screen first, then a menu entry that opens it. Menu entries appear in the normal Games list after the official minigames. The six-button home layout is unchanged. 

function on_init()
    api.register_screen({
        "id": "garden",
        "title": "My Garden",
        "draw": draw_garden,
        "on_open": open_garden,
        "on_close": close_garden,
        "on_action": garden_action,
        "on_pointer": garden_pointer,
        "on_key": garden_key,
        "on_update": garden_update
    })
    api.register_menu_entry({
        "label": "My Garden",
        "screen": "garden",
        "order": 10
    })
end
KeyArgumentsPurpose
idstringLocal id; the runtime prefixes it with the mod id.
titlestringHeader text.
drawctxRequired. Rebuilds the frame.
on_open, on_closenoneLoad and save screen state.
on_actioneventA button or hit region was activated; event.hit is its id.
on_pointereventPointer movement, press or release.
on_keyactionleft, right, up, down, accept or cancel.
on_updatedeltaRuns while the screen is open.

Menu entries may also include an optional available function. The host calls it when building the Games list; return false to hide the entry. This lets a mod implement its own unlock conditions without changing official progression totals.

Screen content is drawn in a 308 × 189 logical space below Dejinochi’s standard title and Back bar. Use the normal Back control or Escape to leave; on_close then runs.

Complete screen example

var seeds = 3
var message = "Click the plot."

function draw_garden(ctx)
    ctx.rect(0, 0, ctx.width, ctx.height, "transparent")
    ctx.sprite(soil_image, 24, 20, 2)
    ctx.text(20, 84, "Seeds: " + str(seeds), 12, "ink")
    ctx.text(20, 100, message, 10, "dim")
    ctx.button("plant", 20, 124, 120, 28, "Plant a seed", {"enabled": seeds > 0})
    ctx.hit("plot", 20, 16, 48, 48, {"hover": "The garden plot"})
end

function garden_action(event)
    if event.hit == "plant" and seeds > 0:
        seeds = seeds - 1
        message = "Planted."
    elif event.hit == "plot":
        message = "This plot is ready."
    end
end

        api.close_screen()
    end
end

Minigames

A registered minigame appears in the normal Games list and starts through the ordinary gameplay flow. Dejinochi still owns completion, happiness rewards, hunger and sleep costs, fatigue, gifts, pet reactions and saving. Your mod controls only the round’s simulation and presentation. 

function on_init()
    api.register_minigame({
        "id": "catch_bugs",
        "title": "Catch the Bugs",
        "on_start": start_bugs,
        "on_update": update_bugs,
        "on_pointer": pointer_bugs,
        "on_key": key_bugs,
        "draw": draw_bugs,
        "status": status_bugs,
        "on_finish": finish_bugs,
        "on_cancel": cancel_bugs
    })
end
KeyArgumentsPurpose
id, titlestringsLocal id and display title.
drawctxRequired. Draw the full 308 × 231 canvas.
on_startnoneRound begins; reset mod-side state.
on_updatedeltaAdvance the simulation while active.
on_pointer, on_keyevent / actionInput for the round.
statusnoneReturn the top-caption text.
on_finishwonThe host accepted the result; apply mod-side rewards here.
on_cancelnoneThe round was left before completion.
availablenoneOptional unlock check; return false to hide the game.

Finish a round with api.finish_minigame(true) or api.finish_minigame(false). Do not call it from on_finish. Modded games do not count toward the four official minigame achievements, minigame gifts or the demo’s official-game limit. 

var caught = 0
var running = false

function start_bugs()
    caught = 0
    running = true
end

function update_bugs(delta)
    if not running:
        return
    end
    if caught >= 3:
        running = false
        api.finish_minigame(true)
    end
end

function pointer_bugs(event)
    if running and event.type == "press" and event.hit == "bug":
        caught = caught + 1
    end
end

function draw_bugs(ctx)
    ctx.text(8, 8, "Caught " + str(caught) + " / 3", 14, "ink")
    ctx.sprite(bug_image, 80, 70, 2)
    ctx.hit("bug", 80, 70, 32, 32)
end

function status_bugs()
    return "Catch three bugs!"
end

Periodic updates

Use a screen or minigame on_update for per-frame work, or request a low-rate global timer: 

function on_init()
    api.register_update(tick_garden, 2.0)   # about twice per second
end

function tick_garden(delta)
    # Grow, decay, schedule or autosave.
end

The rate is clamped to 0.1–30 Hz. Dejinochi deliberately avoids calling every mod every rendered frame, and timers continue while the window is minimized. Prefer timestamps from api.now() over assuming a fixed frame rate.

Applying pet effects

apply_effect is the only way to change the pet. Allowed kinds are happiness, hunger, health, sleep and care. Amounts are validated, limited to ±50, clamped to the pet’s normal 0–100 range, and routed through the ordinary gameplay controller. 

api.apply_effect("happiness", 2, "garden_harvest")
api.apply_effect("care", 0, "garden_weeding")

Effects record an interaction, save through the normal save path, and emit pet.happiness_changed / pet.effect_applied events. Mods cannot change achievements, Steam statistics, save identity or another mod’s data.

Sound cues

api.sfx accepts a small semantic whitelist: click, confirm, back, denied, success, failure, pickup and happy. Mods cannot load arbitrary audio files.

Persistent storage

Each mod gets a private namespace inside the normal save’s mod_state section. Unknown namespaces are preserved even when the mod is disabled or uninstalled, so reinstalling can restore progression. Mod state follows the same save and Steam Cloud behaviour as other gameplay progression. 

var state = {}

function on_init()
    api.on_migrate(1, migrate_v1)
    state = api.storage_get("garden", default_state())
end

function default_state()
    return {"plots": [], "harvests": 0}
end

function save_garden()
    api.storage_set("garden", state)  # live in the save, written on autosave
    api.storage_save()                # optional immediate save
end

function migrate_v1(from_version)
    state = api.storage_get("garden", default_state())
    if not has(state, "harvests"):
        state.harvests = 0
    end
    save_garden()
    api.set_schema(2)
end
CallPurpose
api.storage_get(key, default)Read a value from the mod’s namespace.
api.storage_set(key, value)Write a value if it passes size/type validation.
api.storage_save()Request an immediate normal save.
api.set_schema(version)Record the mod’s current storage schema.
api.on_migrate(from_version, callback)Run a migration when the stored schema is at that version.

Allowed values and limits

  • nil, booleans, numbers, strings, arrays and dictionaries.
  • 64 KiB per mod and 512 KiB for all mod state.
  • Depth 8; 512 items per array or dictionary; 8,192 characters per string.
  • Engine objects such as textures or nodes are rejected.

Migrations registered at top level run before on_init. Migrations registered inside on_init run after it. If a migration does not advance the schema itself, the host advances it by one to prevent a migration loop.

Content queries

With the content capability, inspect the currently loaded base and modded catalogue. Returned values are plain data; textures are not exposed. 

var forms = api.content_list("forms")
var info = api.content_info("forms", "dejinochi.form.kerochi")
api.log(info.name)
CallReturns
api.content_list(kind)Array of ids. Kinds: forms/pets, shells, stickers, assets.
api.content_info(kind, id)Sanitized metadata dictionary, or {} when missing.

Images & assets

Load images from your own mod folder. Only PNG, JPEG and WebP are accepted, up to 2 MiB and 1024 pixels per side. The returned asset id is used by ctx.sprite. 

var soil_image = ""

function on_init()
    soil_image = api.load_image("assets/soil.png")
    var size = api.image_size(soil_image)
    api.log(str(size.width) + "x" + str(size.height))
end

function draw_garden(ctx)
    ctx.sprite(soil_image, 20, 20, 2)
end

Paths are relative to the mod root. Absolute paths, .., unsupported extensions and images outside the mod are rejected.

Security model

Treat every Workshop item as untrusted. Dejinochi does not load mod GDScript, native code, scenes or resource packs. It parses and interprets DejiScript itself, and the host performs every privileged operation after validation.

Isolation guarantees

  • No scene tree, nodes, engine objects or global GDScript scope.
  • No OS, filesystem, network, Steam or resource loader access.
  • No arbitrary native code or Godot resources.
  • Separate interpreter, API object, registrations, timer list and storage per mod.
  • Images are loaded only from the owning mod’s package, with size and type checks.
  • Drawing commands, arguments, effects and stored data are validated.
  • Step, wall-clock, recursion, loop, collection, string, draw and storage budgets.
  • A failing mod is stopped without crashing the game or other mods.

Residual risk. The sandbox is designed for untrusted content but is still software. Report interpreter or host-validation bugs instead of assuming absolute security. Mods can still consume their allowed CPU and storage budgets, and a mod with broad declared capabilities can intentionally affect the pet through the validated API.

Testing & debugging

  1. Install the mod and restart Dejinochi.
  2. Enable it in Settings → Mods → Installed mods.
  3. Watch the Godot output for [Mod your.mod.id] lines.
  4. Use api.log(...) and print(...) while iterating.
  5. Open the Mods detail screen to review capabilities and validation errors.
  6. Disable and re-enable after editing, or restart, because loaded code is not hot-swapped.

Useful checks

  • Does the mod appear in the Mods list? A manifest/id/entry error prevents loading.
  • Does the Games entry appear? Check registration and the optional available callback.
  • Does a callback fail only after a certain action? Check capability declarations and arguments.
  • Does saved state disappear? Confirm storage_set succeeds and the dataset is within limits.
  • Did a Workshop update change the script? Restart to load the new code.

Publishing to Steam Workshop

Code and data mods use the same folder and uploader flow. The uploader validates the package but never executes the mod’s script.

Before publishing

  • Test the folder locally from the normal mods directory.
  • Use a clean folder containing only the mod and its preview image.
  • Include a complete manifest with a stable namespaced id.
  • Do not include private notes, credentials, project files, .git, .godot or .env.

Upload

  1. Start Steam and launch the bundled Mod Uploader.
  2. Select the mod folder (the folder containing manifest.json).
  3. Enter a title and description; choose a PNG/JPEG preview smaller than 1 MiB.
  4. Keep visibility Private for the first test.
  5. Leave the item id empty to create a listing, or use an existing id to update it.
  6. Publish and wait for Steam’s result.
  7. Accept Steam’s Workshop agreement if prompted, then open the item page.

Steamworks prerequisites

  • Enable ISteamUGC for file transfer for App ID 5277000.
  • Configure Steam Cloud byte/file quotas for Workshop preview images.
  • Keep Workshop visibility at Developers Only or Developers & Testers while testing.
  • Use the full-game build with the uploader launch option; publishing is unavailable in demo builds.

Updates

Publish to the same item id to update. Subscribers receive the new folder from Steam. If the update changes the script or manifest, the running game stops the old code and asks for a restart before executing the new version. If it raises api_version beyond the running game, the mod fails safely with a compatibility message.

See docs/workshop.md in the game repository for the complete Steamworks setup, result-code troubleshooting and manual acceptance checklist.

API versioning

api_version is a contract, not the mod’s own version. API version 1 is implemented by Dejinochi 1.1.x. Future additions keep existing names and meanings; breaking changes require a new API version. A mod requesting a newer API is rejected rather than run with mismatched assumptions.

Use min_game_version for content or game-fix dependencies that are separate from the API shape. Keep your own version field for player-facing release notes and Workshop updates.
